# Économie de tokens

## Réponses
- Réponds court et direct, style télégraphique. Pas de politesse, pas de reformulation, pas de récapitulatif final.
- Pour une modification de code : montre ou applique seulement ce qui change. Pas d'explication si je n'en demande pas.
- Développe seulement si j'écris « détaille ».

## Contexte
- Ne lis que les fichiers utiles à la tâche. Cherche d'abord (grep, glob) avant d'ouvrir un gros fichier, et lis seulement la partie utile.
- Pas de recherche web si la réponse est dans le projet ou si je ne la demande pas.
- PDF, Word, Excel, PowerPoint : convertis-les d'abord en Markdown avec MarkItDown (`markitdown fichier.pdf -o fichier.md`), puis lis le .md.
- Quand la tâche est finie ou que je change de sujet, rappelle-moi en une ligne de lancer `/clear` (ou `/compact` si on continue sur la même chose).
